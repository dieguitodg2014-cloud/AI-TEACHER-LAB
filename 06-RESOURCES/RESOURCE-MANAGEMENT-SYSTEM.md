# RESOURCE MANAGEMENT SYSTEM

## Version
1.0

## Purpose

The Resource Management System defines how AI TEACHER LAB identifies, creates, selects, organizes, evaluates, reuses, adapts, and retires instructional resources.

Resources support pedagogy. They do not define pedagogy.

## Core Principle

**A resource is valuable only when it contributes to a defined learning purpose.**

The system must avoid resource accumulation for its own sake.

## Resource Categories

Resources may include:

- teacher guides
- lesson plans
- worksheets
- readings
- listening scripts
- audio
- video
- images
- diagrams
- presentations
- games
- communicative task cards
- assessment materials
- rubrics
- templates
- prompts
- vocabulary banks
- grammar reference materials
- real-world materials
- digital activities
- technology instructions

## Resource Metadata

Whenever practical, resources should be identifiable by:

- title
- resource type
- target level
- learner profile
- skill/function
- language focus
- communicative purpose
- estimated time
- required materials/technology
- related lesson, unit, or project
- version
- status

## Resource Selection

Before creating a new resource, the system should determine whether an existing resource can be:

1. reused as-is
2. adapted
3. combined with another resource
4. replaced because it is unsuitable
5. newly created because no adequate resource exists

This prevents unnecessary duplication.

## Resource Quality Criteria

A resource should be evaluated for:

- pedagogical relevance
- level appropriacy
- language accuracy
- clarity
- communicative value
- accessibility
- feasibility
- visual/usability quality
- assessment alignment when applicable
- cultural appropriacy

A visually attractive resource is not automatically a good resource.

## Resource-to-Objective Alignment

Every important resource should answer:

**What does this resource help learners do?**

If the answer is unclear, the resource should not automatically be included.

## Level Control

Resources must respect the Level Control Engine.

Level adaptation must consider more than vocabulary difficulty. It may require changes to:

- objective
- language load
- cognitive demand
- scaffolding
- interaction
- output
- accuracy expectations
- fluency expectations
- register
- autonomy

The same resource may therefore require substantive redesign at another level.

## A0 Resource Rules

For true beginners:

- provide necessary language before expecting independent production
- avoid unexplained grammar or vocabulary
- keep instructions highly accessible
- use visual, contextual, gestural, and modeled support when useful
- control language load carefully
- prioritize meaningful oral production
- avoid worksheets that test knowledge learners have not been taught

## Resource Creation Pipeline

**Need → Purpose → Specification → Draft → Pedagogical Review → Language Review → Usability Review → Final Resource**

AI-generated resources must pass quality control before being treated as classroom-ready.

## Resource Adaptation

Adaptation should preserve the original pedagogical purpose unless the request explicitly changes it.

Possible adaptations include:

- level adaptation
- age adaptation
- modality adaptation
- time reduction or expansion
- individual/pair/group adaptation
- online/in-person adaptation
- accessibility adaptation
- cultural/contextual adaptation
- teacher-led to learner-led adaptation

## Resource Reuse

Reused resources should be checked against the current:

- learner profile
- level
- objectives
- context
- timing
- assessment requirements

A resource that was successful in one class is not automatically appropriate for another.

## Resource Dependencies

Some resources depend on prior materials or language.

Dependencies should be identified when a resource:

- assumes previous vocabulary
- assumes previous grammar
- requires a model
- requires technology
- requires another worksheet or text
- forms part of a project sequence

The system must not create hidden dependencies that make classroom implementation fail.

## Teacher Usability

A classroom resource should make implementation easier, not create unnecessary teacher workload.

Where appropriate, teacher-facing resources should include:

- objective
- preparation requirements
- materials
- procedure
- timing
- grouping
- answer key
- anticipated difficulties
- feedback guidance

Learner-facing resources should avoid unnecessary teacher-only information.

## Digital and AI-Generated Resources

AI tools may generate:

- images
- slides
- audio
- video
- formatted documents
- visual organizers
- alternative versions

However, the pedagogical design must come from the AI TEACHER LAB system.

Secondary tools must not silently change the intended level, objective, assessment construct, or communicative purpose.

## External and Real-World Materials

Authentic materials may be used when they provide meaningful learning value.

The system should consider:

- authenticity
- difficulty
- relevance
- length
- cultural context
- copyright/access considerations
- necessary scaffolding

Authenticity alone is not sufficient justification for classroom use.

## Resource Versioning

When a resource is substantially changed, the system should treat it as a new version.

Version changes may result from:

- level redesign
- correction of errors
- structural redesign
- assessment changes
- major context changes
- accessibility improvements

Minor formatting changes do not necessarily require a new pedagogical version.

## Resource Status

Resources may be classified as:

- Draft
- Under Review
- Classroom Ready
- Needs Revision
- Retired

Only resources that have passed the appropriate quality checks should be labeled Classroom Ready.

## Resource Library Structure

The repository may organize resources by function, level, project, or resource type. The structure should remain understandable to a teacher who did not create the original resource.

Organization must prioritize retrieval and reuse over excessive categorization.

## Quality Control Integration

The Quality Control Engine should review resources according to their role.

A worksheet requires different checks from a lesson plan, assessment, presentation, or audio script.

At minimum, the review should consider:

1. purpose
2. level
3. language accuracy
4. alignment
5. usability
6. communication value
7. feasibility

## Resource Retirement

A resource should be retired when it is:

- pedagogically obsolete
- inaccurate
- repeatedly ineffective
- incompatible with the current system
- unnecessarily duplicated
- too dependent on unavailable technology

Retirement prevents the resource library from becoming a collection of outdated materials.

## Resource Governance

The Master System has final authority over pedagogical intent.

The Project Design Engine determines project-level resource needs.

The ESL Lesson Engine determines lesson-level resource needs.

The Assessment Engine governs assessment resources.

The Level Control Engine governs level appropriacy.

The Quality Control Engine validates quality.

## Final Resource Gate

Before a resource is classroom-ready, verify:

- clear purpose
- correct level
- accurate language
- appropriate cognitive demand
- meaningful use
- realistic timing
- feasible implementation
- appropriate scaffolding
- alignment with the lesson/project
- acceptable usability

## System Principle

AI TEACHER LAB should build a **curated instructional resource system**, not a warehouse of AI-generated files.

The goal is fewer, better, reusable resources that serve clearly defined learning purposes.
